# pactrun plan, October 2026

What recent news and research mean for pactrun, what this round already
changed, and what comes next. Sources are Deep Learning Weekly issues 472, 473
and 475 (September 11 to October 2, 2026) plus the articles and papers behind
them. Each item names the source, the fact that matters, and the change.

## Done in this round

| # | Source | What it showed | Change |
|---|---|---|---|
| 1 | Prompt-caching cost write-ups (token efficiency for long agent runs) | Long agent runs are mostly cached input. A cache read bills at about a tenth of the normal input rate. | **Bug fixed.** No adapter handled caching. Anthropic under-counted tokens (cache reads and writes were dropped), OpenAI over-counted cost (cached input billed at full price), Gemini dropped thinking and tool-use input tokens, and the `wrap()` pre-call gate priced cache writes at the normal rate. `Event` now carries `cache_read_tokens`, `cache_write_tokens` and `reasoning_tokens`, each adapter prices them separately, and the OTel span reports them. Example, 100k cached + 2k fresh input + 1k output: Anthropic Sonnet goes from 3,000 tokens / $0.021 to 103,000 / $0.051, and gpt-4.1 from $0.212 to $0.062. |
| 2 | Emergence World (arXiv 2609.17320) | Injected content was written into persistent memory by the agents themselves and acted on up to 46 hours later. Spotting the attack did not stop it. | New check `no_untrusted_memory_write` (OWASP ASI06): flags a memory write that copies untrusted text, or, in strict mode, any memory write after untrusted input. |
| 3 | Agent consistency study (AppWorld: 77.4% average, 53.0% right on all 5 repeats) | One good run says little about the next one. | `pactrun test` takes `traces:` (a list or a glob of repeated runs of one task). A test passes only if every run gets the right verdict, and the report shows Pass^k and Mean@k. |
| 4 | Read-only database tools for agents | Regex SQL checks and session flags are bypassed by a delete inside a CTE, a side-effect function, or turning the flag back off. Only an engine-level lock holds. | `docs/LIMITATIONS.md` lists these bypasses for `no_destructive_args` and says to enforce read-only in the database. |
| 5 | Pydantic AI capabilities API | The framework can now stop a tool from running. | Pydantic AI adapter shipped (`f660a52`), along with three detection fixes found while scripting attacks. |

## Next (P1)

| # | Source | Change | Notes |
|---|---|---|---|
| 6 | OTel GenAI semantic conventions (still unreleased) | Add an `invoke_agent` root span, `gen_ai.conversation.id`, `gen_ai.agent.name` and `gen_ai.tool.call.id`. Emit the new `gen_ai.client.inference.usage.*` token counters and the operation duration histogram. Report violations as `gen_ai.evaluation.result` events. | The older `gen_ai.client.token.usage` metric has been replaced. Some tutorials still describe it, so skip it. Keep the observer labelled experimental until the conventions are released. |
| 7 | Suspend/resume agent runtimes (dormant agents resumed in under a second) | `Session.restore(trace)` rebuilds budgets and history from a `TraceRecorder` file without firing checks again. Add a way to pause the wall clock while a run is suspended. | Today a process restart resets every budget to zero, which is a fail-open for long-running agents. |
| 8 | Denial-of-wallet paper (arXiv 2609.28585) | Two new checks: one that caps how fast the prompt grows across calls, and one that caps consecutive tool-only turns. | Tool output kept in history is billed again on every later call. Needs item 1, which is done. |
| 9 | Agent payments (single-use cards, delegated-payment allowances) | A check that caps money moved by tools: per-call and per-run limits read from a tool argument, with currency, merchant allowlist and expiry. | Fields follow the published allowance shape (`max_amount` in minor units, `currency`, `merchant_id`, `expires_at`). |
| 9b | Found while fixing item 1 | Refresh the model price tables against the providers' pricing pages. Several entries are out of date, and some of them under-count (claude-haiku-4-5, gpt-4.1-mini, o4-mini), which lets spend pass `cost_under`. A dated model name such as `gpt-5.4-mini-…` matches the `gpt-5.4` entry first. The pre-call estimate never counts tool-definition tokens. | Under-counting is a fail-open, so this goes first in P1. |
| 10 | Error budgets for agent behavior | Per-clause pass and total counts that SLO tools can read, plus a summary over a folder of traces (`pactrun replay` on many runs) giving each check's violation rate. | The article sets separate targets per behavior, e.g. 95% over 30 days. pactrun clauses already map to behaviors one to one. |

## Later (P2)

| # | Source | Change |
|---|---|---|
| 11 | OWASP Agent Control Standard v0.1.0 | Serve a contract as a guardian over the standard's JSON-RPC protocol (19 hooks, decisions allow / deny / modify / ask / defer, signed requests). No Python implementation exists yet, so this is the biggest interop opening. It needs a decision object that can modify or defer, which pactrun lacks today. |
| 12 | Network sandbox with a policy prover | A `pactrun check candidate.yaml --within boundary.yaml` command that proves one contract's tool and host allowlists stay inside another's, and an export of `tool_host_within` allowlists to a sandbox network-policy file. The sandbox controls the network edge. pactrun covers what the edge can't see: argument meaning, taint, cost and call order. |
| 13 | Skill registries (1M skills, with audits finding injection in about a third of sampled skills) | Extend `tool_definitions_stable` to skills: fingerprint a skill's definition and flag one that changes mid-run or doesn't match a pinned hash. |

## Parked

- **Scripted attack benchmark.** A safety check stopped two attempts to write
  the attack scenarios, including one using only labelled placeholder
  payloads. The partial files are kept out of the repository. To revisit with
  a human-written corpus or a licensed public one.

## Not for pactrun

- **New model prices.** Prices quoted in news coverage are not added to the
  adapter tables until they appear on the provider's pricing page. Where a
  framework reports its own cost, pactrun uses that.
- **LLM-as-judge comparisons, memory curation, deep-search agents, model
  routing.** These are evaluation or agent-design topics, not runtime
  guardrails.
- **Action gating in hosted agent products** (allow, require approval, block)
  matches pactrun's existing `block` and `approve` actions. No change needed.

## Needs the CI owner

CI configuration is not changed from this repository's day-to-day work.

- The adapters job installs a fixed list of SDKs that leaves out
  `pydantic-ai-slim`, so the Pydantic AI adapter tests skip in CI.
- Python 3.15 is released (October 1, 2026) and not in the test matrix.
  Python 3.10 reaches end of life around October 31, 2026.
- `setup-uv` and `setup-python` are several major versions behind.
