# pactrun plan, October 2026

What recent news and research mean for pactrun, what this round already
changed, and what comes next. Sources are Deep Learning Weekly issues 472, 473
and 475 (September 11 to October 2, 2026) plus the articles and papers behind
them. Each item names the source, the fact that matters, and the change.

## Done in this round

| # | Source | What it showed | Change |
|---|---|---|---|
| 1 | Prompt-caching cost write-ups (token efficiency for long agent runs) | Long agent runs are mostly cached input. A cache read bills at about a tenth of the normal input rate. | **Bug fixed.** No adapter handled caching. Anthropic under-counted tokens (cache reads and writes were dropped), OpenAI over-counted cost (cached input billed at full price), Gemini dropped thinking and tool-use input tokens, and the `wrap()` pre-call gate priced cache writes at the normal rate. `Event` now carries `cache_read_tokens`, `cache_write_tokens` and `reasoning_tokens`, each adapter prices them separately, and the OTel span reports them. Example, 100k cached + 2k fresh input + 1k output: Anthropic Sonnet goes from 3,000 tokens / $0.021 to 103,000 / $0.051, and gpt-4.1 from $0.212 to $0.062. |
| 2 | Emergence World (arXiv 2609.17320) | Injected content was written into persistent memory by the agents themselves and acted on up to 46 hours later. Spotting the attack did not stop it. | New check `no_untrusted_memory_write` (OWASP ASI06): flags a memory write that copies untrusted text, or, in strict mode, any memory write after untrusted input. |
| 3 | Agent consistency study (AppWorld: 77.4% average, 53.0% right on all 5 repeats) | One good run says little about the next one. | `pactrun test` takes `traces:` (a list or a glob of repeated runs of one task). A test passes only if every run gets the right verdict, and the report shows Pass^k and Mean@k. |
| 4 | Read-only database tools for agents | Regex SQL checks and session flags are bypassed by a delete inside a CTE, a side-effect function, or turning the flag back off. Only an engine-level lock holds. | `docs/LIMITATIONS.md` lists these bypasses for `no_destructive_args` and says to enforce read-only in the database. |
| 5 | Pydantic AI capabilities API | The framework can now stop a tool from running. | Pydantic AI adapter shipped (`f660a52`), along with three detection fixes found while scripting attacks. |

## Parked

## Not for pactrun

- **New model prices.** Prices quoted in news coverage are not added to the
  adapter tables until they appear on the provider's pricing page. Where a
  framework reports its own cost, pactrun uses that.
- **LLM-as-judge comparisons, memory curation, deep-search agents, model
  routing.** These are evaluation or agent-design topics, not runtime
  guardrails.
- **Action gating in hosted agent products** (allow, require approval, block)
  matches pactrun's existing `block` and `approve` actions. No change needed.

## Needs the CI owner

CI configuration is not changed from this repository's day-to-day work.

- Python 3.10 reached end of life on October 1, 2026, and Python 3.15.0 was
  released on October 9. The test matrix runs 3.10 to 3.14. Dropping 3.10
  from `requires-python` needs the matrix changed in the same change.
- On Python 3.15, litellm (which declares `requires_python <3.15`) can't be
  installed, and pydantic-ai-slim 2.55+ needs Python 3.11 or later.
- The adapters job installs a fixed list of SDKs that leaves out
  `pydantic-ai-slim`, so the Pydantic AI adapter tests skip in CI.
- `setup-uv` and `setup-python` are several major versions behind.
